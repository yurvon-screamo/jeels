## 1. Суть

Сегодня новые карты впрыскиваются прямо в SRS-урок (`build_lesson_core` →
`collect_core_new_cards`) — пользователь получает новую информацию без введения,
десятки новых карт в день «мешаются в кашу».

Фича вводит обязательную стадию знакомства: партия новых карт проводится через
спокойный показ и тренировку до критерия, затем **вся партия целиком** входит в
интервальное расписание с первым ревью назавтра.

Научная основа — successive relearning (Rawson & Dunlosky): retrieval practice
до критерия + внутриротационный spacing + повторное прохождение назавтра
(первое ревью и есть повторка).

## 2. Глоссарий

| Термин | Значение |
|---|---|
| **Пул** | Очередь незнакомых карт в порядке приоритета (существующая политика: JLPT-приоритет, N5 первым) |
| **Рука** | Партия незнакомых карт (до 7), обрабатываемая за один урок. Атомарна и эфемерна |
| **Виток** | Один полный проход всей руки в случайном порядке |
| **Подфаза** | Этап тренировки слов с одним направлением (яп→рус, затем рус→яп) |
| **Критерий** | Требуемое число успешных ответов карты в подфазе (3) |
| **Слова руки, содержащие кандзи** | Новые слова этой же руки, использующие знак данного кандзи. Не путать с существующим механизмом `kanji_companions` (подтягивание известных слов в обычные уроки) — он не затрагивается |

## 3. Взаимодействие с SRS-состоянием

- Ответы в тренировке **не записываются** в историю памяти карт (`MemoryHistory`),
  не вызывают штатный рейтинг (`rate_memory`/`apply_review`) и не влияют на
  статистику повторений.
- Исключение — действие **«Уже знаю»** фазы показа: оно идёт существующим
  механизмом mark-as-known (`MarkCardAsKnownUseCase`) и создаёт состояние памяти.
- Планирование первого ревью выполняется ровно один раз — при закрытии руки:
  каждой карте создаётся начальное `MemoryState` с датой первого ревью назавтра.
  Механизм сидирования — решение технического этапа (см. §9.2, риск R1).

## 4. Учёт дневного лимита

- Лимит тратится **одной операцией при закрытии руки** (все карты руки).
- Тренировочные ответы и прерывание путь учёта лимита не используют
  (текущий по-рейтинговый инкремент в `update_history` для карт руки недостижим).
- «Уже знаю» лимит не тратит; замена слота новой картой размер руки не
  меняет — лимит списывается при закрытии руки за фактически сидированные.

## 5. Совместимость и миграции

- Миграций схемы **нет**: сидирование пишет в существующую `Option<MemoryState>`
  внутри `MemoryHistory`; новых таблиц/полей персистентности нет; состояние руки
  нигде не сохраняется.
- Режим включён в сборке постоянно; откат — revert коммитов срезов S0–S7
  (миграций нет, состояние руки нигде не персистится).
- Структура `User`/`KnowledgeSet` не меняется.

## 6. Дефолтные параметры

| Параметр | Значение |
|---|---|
| Размер руки | min(7, остаток пула, остаток дневного лимита) |
| Критерий | 3 успеха в каждой подфазе (слова: 3× яп→рус + 3× рус→яп); кандзи/грамматика — 3 успеха |
| Константа критерия | `CRITERION_SUCCESSSES: u8 = 3` (не конфиг) |
| Вырожденная рука из 1 карты | допустима (6 подряд показов одного элемента — осознанный случай) |
| Верхняя граница витков/времени | отсутствует (**осознанно**) |
| Копирайт | новые i18n ключи `acquaintance.*`; существующие `lesson.know`/`lesson.dont_know_rating` не изменяются |

## 7. Поведенческая спека (Gherkin v4.1)

```gherkin
# language: ru
Функция: Режим знакомства с новыми картами
  Новые карты (кроме фраз) попадают в интервальное повторение только
  через режим знакомства: рука до 7 карт, показ, тренировка ротациями
  до критерия, затем вся рука целиком входит в расписание с первым
  ревью назавтра.

Правило: Урок содержит максимум одну руку

  Контекст:
    Допустим новые карты никогда не попадают в обычное ревью напрямую
    И дневной лимит ограничивает объём новых карт за день

  Сценарий: Есть новые карты и лимит не исчерпан
    Допустим в пуле есть новые карты
    И дневной лимит сегодня не исчерпан
    Когда юзер начинает урок
    Тогда урок начинается с одной руки знакомства
    И после завершения руки урок продолжается обычным ревью должных карт

  Сценарий: Дневной лимит исчерпан
    Допустим дневной лимит сегодня исчерпан
    И в пуле остались незнакомые карты
    Когда юзер начинает урок
    Тогда урок состоит только из обычного ревью должных карт

  Сценарий: Пул новых карт пуст
    Допустим пул новых карт пуст
    Когда юзер начинает урок
    Тогда урок состоит только из обычного ревью должных карт

Правило: Холодный старт

  Сценарий: Первые дни нового юзера
    Допустим юзер завершил онбординг
    И должных карт для ревью ещё нет
    Когда юзер начинает урок
    Тогда урок состоит только из руки знакомства
    И это осознанная норма первых дней

Правило: Пул новых карт

  Сценарий: Порядок пула
    Допустим формируется рука
    Тогда карты берутся из пула в порядке JLPT-приоритета (N5 первым)
      с пропорцией типов по CARD_TYPE_WEIGHTS (слова:кандзи:грамматика ≈ 80:10:10) —
      тот же контракт, что у исторического впрыска новых карт в урок
    И при исчерпании типа остаток добирается другими типами (fallback)
    И никакая карта не притягивается в руку извне

  Сценарий: Импортированные New-карты
    Допустим юзер импортировал колоду с картами в состоянии «новая»
    Тогда эти карты попадают в общий пул
    И знакомятся через руки на общих основаниях
    И отдельного обхода или ускорения для импорта нет

Правило: Избранное и незнакомые карты

  Сценарий: Избранная незнакомая карта проходит руку как все
    Допустим юзер добавил в избранное карту, не прошедшую знакомство
    Тогда флаг избранного сохраняется
    Но карта попадёт в обычное ревью только после прохождения руки или «Уже знаю»

Правило: Состав руки

  Сценарий: Размер руки
    Когда формируется рука
    Тогда она вмещает до 7 карт
    И берётся столько, сколько позволяют остаток дневного лимита и остаток пула

  Сценарий: Рука атомарна
    Допустим тренировка руки началась
    Тогда рука может перейти в SRS только целиком,
      когда каждая её карта закрыла критерий
    И никакие отдельные карты не переходят в SRS до завершения всей руки

  Сценарий: Слова с кандзи пришли в другой день — ничего не ждут
    Допустим кандзи появился в пуле сегодня
    А слова с этим кандзи выучены давно или придут позже
    Тогда кандзи знакомится без них
    И никакой задержки или переупорядочивания пула не происходит

Правило: Фаза показа

  Сценарий: Действия юзера на слайде
    Допустим показывается очередная карта руки
    Тогда доступны ровно два действия: «Дальше» и «Уже знаю»
    И для карт со звуковым сопровождением звук воспроизводится автоматически
      существующим механизмом приложения
    И повторное прослушивание доступно по нажатию

  Сценарий: «Уже знаю» живёт только здесь
    Допустим показывается карта руки
    Когда юзер нажал «Уже знаю» и подтвердил действие
    Тогда карта помечается известной существующим механизмом
    И немедленно входит в SRS на общих основаниях
    И дневной лимит на неё не тратится
    И её слот в руке занимает новая карта из пула (замена на месте,
      размер руки сохраняется — G-итерация; юзер знакомится с ней сразу)
    И если пул новых карт пуст — карта просто выбывает, рука уменьшается
    И в тренировке действие «Уже знаю» недоступно

  Сценарий: Все карты отмечены известными
    Допустим в фазе показа юзер отметил «Уже знаю» каждую карту руки
    Тогда рука исчезает, не потратив дневной лимит
    И урок продолжается обычным ревью должных карт

  Сценарий: Порядок показа
    Допустим рука содержит кандзи и слова этой руки, содержащие этот кандзи
    Тогда в фазе показа кандзи демонстрируется первым
    И эти слова демонстрируются сразу за ним
    И остальные карты следуют в естественном порядке
    И этот порядок действует только в фазе показа

  Сценарий: Слайд слова
    Допустим в фазе показа карта слова
    Тогда слайд показывает слово, часть речи и переводы
    И фуригана отображается и скрывается строго по логике furigana.rs:
      чтения известных юзеру кандзи скрыты, неизвестных — видны

  Сценарий: Слайд кандзи
    Допустим в фазе показа карта кандзи
    Тогда слайд показывает знак крупно с анимацией черт
    И значения знака
    И чтения, где частые выделены, а редкие приглушены
    И радикалы с их именами
    И несколько популярных слов с этим знаком вместе с переводами

  Сценарий: Слайд грамматики
    Допустим в фазе показа карта грамматики
    Тогда слайд сразу показывает конструкцию, описание, способ образования,
      примеры, полное объяснение и нюансы — всё целиком

Правило: Тренировка — ротации до критерия

  Контекст:
    Допустим ни одна карта не покидает руку до конца тренировки
    И каждая ротация проходит всю руку в случайном порядке,
      включая карты, уже закрывшие критерий текущей подфазы
      либо общий критерий для несловесных карт
    И адаптивные перестановки порядка по результатам ответов отсутствуют

  Сценарий: Виток тренировки
    Допустим идёт тренировка руки
    Когда юзер отвечает по каждой карте: попытка вспомнить, затем раскрытие,
      затем самооценка двумя кнопками «не помню» / «помню»
    Тогда виток считается пройденным, когда отвечена каждая карта руки
    И порядок внутри витка стабилен: ошибка юзера порядок не меняет
      (но сбрасывает шкалу карты — прогресс набора заново)
    И следующий виток начинается в новом случайном порядке

  Сценарий: Закрывшие критерий продолжают отвечаться
    Допустим карта слова А закрыла критерий текущей подфазы
    Или несловесная карта Б закрыла свой общий критерий
    Тогда такая карта продолжает участвовать в ротациях наравне с остальными
    И успешные ответы больше не меняют её прогресс
    И «не помню» переоткрывает карту — шкала текущей подфазы сбрасывается
      в ноль, набор критерия начинается заново

  Структура сценария: Направления и критерии по типам
    Допустим в руке карта типа <тип>
    Тогда тренировка идет по направлению <направление>
    И критерий карты — <критерий>

    Примеры:
      | тип        | направление                                     | критерий                  |
      | слово      | яп→рус, затем рус→яп                            | 3 успеха в каждой подфазе |
      | кандзи     | знак → значение и хотя бы одно частотное чтение | 3 успеха                  |
      | грамматика | пример с конструкцией → её смысл                | 3 успеха                  |

  Сценарий: Несловесные карты между подфазами
    Допустим рука содержит слова, кандзи и грамматику
    Тогда подфазы относятся только к словам
    И кандзи и грамматика копят свои 3 успеха во всех витках обеих словесных подфаз
    И их критерий не зависит от смены словесных подфаз

  Сценарий: Смена подфазы у слов
    Допустим идёт подфаза «яп→рус»
    Когда последний успешный ответ закрывает forward-критерий последнего
      активного слова
    Тогда смена на «рус→яп» происходит НЕМЕДЛЕННО — ровно там, где полоса
      заполнилась (H-итерация UX: полная полоса без перехода путала юзера)
    И счётчики успехов слов обнуляются (шкалы сбрасываются сами)
    И порядок руки перемешивается заново
    И первая карта нового круга не повторяет последнюю карту предыдущего
      (защита стыка при перемешивании)

  Сценарий: Рука без слов
    Допустим рука состоит только из кандзи и/или грамматики
    Тогда подфазы отсутствуют
    И тренировка идёт до закрытия критериев всех карт руки

  Сценарий: Пример грамматики фиксирован
    Допустим тренируется карта грамматики
    Тогда во всех витках используется один и тот же пример правила

  Сценарий: Чтения слов не проверяются
    Допустим тренируется карта слова в любом направлении
    Тогда юзер оценивает только вспоминание перевода или формы
    И чтения усваиваются пассивно через показы и витки

  Сценарий: Упорные провалы без спецобработки
    Допустим юзер ответил «не помню» на одну и ту же карту трижды подряд
    Тогда карта продолжает участвовать в ротациях на общих основаниях
    И никаких блокировок или принудительных мер не появляется
    И верхней границы числа витков или времени сессии нет — это осознанное решение

  Сценарий: Тренировка не пишет в SRS
    Допустим идут фазы показа или тренировки руки
    Тогда ответы юзера не изменяют состояние памяти карт в SRS
    И не учитываются в истории повторений
    И планирование первого ревью произойдёт один раз — при закрытии руки
    Но действие «Уже знаю» фазы показа идёт существующим механизмом
      пометки известной и память меняет

  Сценарий: Конец тренировки
    Допустим слова руки закрыли обе подфазы
    И кандзи и грамматика закрыли свои критерии
    Тогда тренировка завершается
    И появляется переходный экран «Знакомство завершено — к повторению»
      (H-итерация: смена контекста без объяснения путала юзера)
    И кнопка «К повторению» открывает обычное ревью урока
    И если должных карт нет — показывается штатный empty-state урока

  Сценарий: Прогресс виден без «таяния» руки
    Допустим идёт тренировка
    Тогда все карты остаются в ротации до конца
    И прогресс каждой карты отображается отметками на полосе руки

Правило: Завершение и передача в SRS

  Сценарий: Закрытая рука входит в расписание целиком
    Когда тренировка руки завершена
    Тогда вся рука входит в интервальное расписание
    И каждой карте создаётся состояние памяти с первым ревью назавтра
    И это единственный момент планирования для карт руки
    И завтрашнее ревью — обычное, неотличимое от прочих
    И его исход обрабатывает штатная логика SRS

  Сценарий: Переход к ревью
    Допустим юзер нажал «К повторению» на переходном экране
    Тогда та же сессия сразу переходит к обычному ревью должных карт

  Сценарий: Рука завершена, должных нет
    Допустим рука завершена
    И должных карт нет
    Тогда урок завершается штатным образом как урок без ревью

  Сценарий: Лимит тратится рукой целиком
    Допустим рука начала тренировку
    Когда тренировка руки завершилась
    Тогда дневной лимит потрачен на все карты руки одной операцией

  Сценарий: Прерывание возвращает руку целиком
    Допустим рука находится в любой незавершённой фазе — показа или тренировки
    Когда юзер закрыл сессию
    Тогда вся рука возвращается в верхушку пула
    И дневной лимит не тратится вовсе
    И следующий урок предложит руку из этих же карт,
      если состав пула не изменился

  Сценарий: Удаление карты посреди руки
    Допустим карта удалена из словаря во время любой незавершённой фазы руки
    Тогда рука продолжает работу без неё
    И если незакрытых карт не осталось — рука считается завершённой
    И входит в SRS как обычно

  Сценарий: Рука через смену суток
    Допустим рука начата в один календарный день приложения
    И завершена после смены дня
    Тогда дневной лимит списывается в день завершения руки
    И первое ревью назначается на день, следующий за днём завершения
    И границей дня служит существующая граница дня приложения

Правило: Пропуск дней

  Сценарий: Пропущенные дни не создают задолженности
    Допустим юзер не заходил несколько дней
    Когда он начинает урок
    Тогда рука формируется в пределах обычного дневного лимита
    И объём новой порции не зависит от числа пропущенных дней

Правило: Границы механики

  Сценарий: Фразы вне режима
    Допустим в системе появилась новая фраза
    Тогда фраза попадает в обычное SRS-ревью напрямую
    И режим знакомства её не касается

  Сценарий: Незнакомые карты не просачиваются в ревью
    Допустим рука не завершена и вернулась в пул
    Тогда её карты не могут появиться в обычном ревью
    Даже если какая-то из них в избранном
```

## 8. UI Specification

Дизайн-система: `DESIGN.md` (Origa Design System, «типографика печатного станка
на японской бумаге»). Всё собирается из готовых токенов и компонентов; новые
элементы — HandProgressStrip, DirectionIndicator, AcquaintanceSlide ×3 типов,
summary-экран.

### 8.1 UX-принципы

1. Режим живёт **внутри существующей страницы `/lesson`**, тот же каркас
   карточки (`card-layout-lesson`, bg-paper, 1px border-dark, hard shadow ::after).
2. Хедер: слева — Tag фазы, отдельный компактный Tag направления, Tag типа
   карты и Tag части речи (wrap на нескольких строках); справа — полоса
   руки и кнопка озвучки текущего слова (иконка Play, не звук — чтобы не
   конфликтовать с mute урока). Мобильная вёрстка: блоки переносятся.
3. Полоса руки — **единственный** индикатор прогресса во время знакомства:
   счётчик ревью-карт в хедере скрыт (F-итерация). В показе ячейки
   заполняются по пройденным слайдам, в тренировке — успешными ответами
   карт; полоса дублируется текстом (aria-label, §8.4).
4. Тренировка переиспользует рефлекс урока: раскрытие → две кнопки [1]/[2].
5. «Не помню» — нейтральный по стилю (без красной подсветки), но не
   нейтральный по эффекту: шкала карты в текущей подфазе сбрасывается
   в ноль — набор критерия начинается заново; в том числе у карты,
   уже закрывшей критерий (I-итерация; сброс закрывших — позднейший
   баг-фикс: заморозка касалась только успешных ответов).

Без отдельного экрана-заголовка: урок с новыми картами открывается сразу первым
слайдом показа; смену режима считывают Tag фазы и полоса руки. Итогового
экрана руки нет (F-итерация): закрытая рука сразу открывает ревью урока.

### 8.2 Анатомия экрана

```
┌──────────────────────────────────────────────┐
│ ЗНАКОМСТВО · ПОКАЗ                    [N/M]  │ ← Tag фазы + счётчик
│ ▰▰▰▱▱▱▱                                     │ ← полоса руки
│ ┌────────────────────────────────────────┐  │
│ │           КОНТЕНТ СЛАЙДА               │  │  ← card-layout-lesson
│ └────────────────────────────────────────┘  │
│  [Уже знаю]                  [Дальше →]     │ ← action bar (только фаза показа)
└──────────────────────────────────────────────┘
```

**Слайд слова:** слово крупно (Cormorant/Noto Sans JP, ~64px) с фуриганой
по логике `furigana.rs` и превью кандзи при наведении/тапе (как в уроке,
`with_kanji_tooltip`); переводы (body-lg mono); аудио воспроизводится
автоматически (гарды урока: TTS доступен и звук не выключен). Повтор —
кнопкой-динамиком в шапке рядом с полосой руки (G-итерация, из тела слайда
убрана): видна, только когда японская сторона слова на экране — на
Reverse-фронтa кнопка спрятана, чтобы не подсказывать ответ голосом;
несловесные карты кнопку скрывают. POS-тег части речи («Глагол» и т.п.)
живёт в шапке с остальными тегами (G-итерация).

**Слайд кандзи:** знак ~160px с анимацией черт (`.kanji-animation-svg`);
значения; ОН/КУН чтения — частотные fg-black weight 500, редкие fg-light;
радикалы Tags; популярные слова с переводами (serif + mono).

**Слайд грамматики:** конструкция (headline-sm) → короткое описание →
how_to_form в блоке bg-warm → примеры → explanation + nuances **целиком сразу**
(юзер впервые видит правило). Карточка скроллится (`min-h` ADR-031),
action bar прибит к низу, нижний fade bg-paper сигнализирует обрезку.

**Тренировка:** фронт по направлению → `[Показать]` [Space]
(паттерн next_card_button) → раскрытие: фронт остаётся сверху уменьшенным
и приглушённым, под divider — ответ (G-итерация, как в обычном уроке) →
RatingButtons «Не помню» [1] (Default) / «Помню» [2]
(Olive). Рус→яп: ответ = слово + фуригана + повтор аудио. Фронты не утекают
ответ (F-итерация): кандзи — только знак (значение и частотные чтения — в
ответе, готовый ReadingGroup); грамматика — японская строка первого примера
без перевода (`grammar_example_front`; пустые examples вырождаются в
заголовок конструкции), ответ = смысл + полный пример с переводом.
Forward-фронт слова озвучивается автоматически (единый предикат с показом).

**Полоса руки:** N ячеек по числу карт; заполнение ячейки = засечки успехов
текущей подфазы (olive fill, 0–3); закрытая подфаза — полные ячейки; смена
подфазы — сброс анимацией anima-fade (200ms); несловесные карты заполняются
сквозь обе подфазы. Ячейки не исчезают (прогресс не тает).

**Переходный экран (H-итерация):** «Знакомство завершено» + пояснение про
первое повторение + кнопка «К повторению» (Filled) — одно понятное действие
между тренировкой и ревью; при пустом ревью после кнопки показывается
штатный empty-state урока.

### 8.3 Interaction States

- **«Уже знаю»** — Ghost-кнопка слева action bar; клик → общий паттерн
  ConfirmModal (Modal + Ghost-отмена + Filled-подтверждение, выделен из
  DeleteConfirmModal — F-итерация): «Отметить известной?» / «Да, знаю» /
  «Нет». «Да» → карта помечается известной, выбывает из руки (ячейка
  схлопывается, 200ms), «Нет»/Escape → возврат.
- Последняя карта показа → автопереход в тренировку без промежуточного экрана.
- Клавиатура: Space = показать/дальше, [1]/[2] = оценка — те же хендлы, что в
  `keyboard_handler.rs` урока.
- Прерывание — без модальных подтверждений (рука молча возвращается в пул);
  единственная защита от случайного выхода — штатный beforeunload WebView.

### 8.4 Accessibility & Texts

- Контраст AA на существующей паре fg-black/bg-paper; fg-light — только редкие
  чтения, не body-текст.
- Полоса руки дублируется текстом «N из M карт · K/V успехов» (aria-label);
  цвет делений не единственный индикатор.
- Кнопки ≥44px высоты; `anima-focus-ring` для клавиатурной навигации;
  `prefers-reduced-motion` гасит анимации штатно.
- Новые i18n ключи `acquaintance.*` (EN+RU, leptos_i18n): названия фаз,
  «Уже знаю», «Да, знаю», «Не помню», «Помню», «Рука закрыта», «К ревью».

impl AcquaintanceHand {

    /// (SelectAcquaintanceHandUseCase) и только валидирует:
    /// Phrase -> Err, дубликаты -> Err, пустота -> Err. В словарь не ходит.

    /// Ответ карты: успех продвигает счётчик, ошибка сбрасывает шкалу

    /// при полностью выведенных словах — false. Вызывается UI ровно один
    /// раз после последней карты витка.
    pub fn advance_subphase_if_words_done(&mut self) -> bool;
    pub fn is_complete(&self) -> bool;           // слова — обе подфазы; несловесные — общий критерий
}

### 9.3 Срезы (risk-first, линейные)

| Срез | Содержание | Критерий приёмки |
|---|---|---|
| **S0** | Спайк сидирования + каркас: доказать семантику MemoryState::with_card_state; флаг `acquaintance_mode` в origa_ui; скелет модуля | Юнит «seed → !is_new, due=завтра, !is_known_card, apply_review(Good) → интервал ≥1 дня и короче потолка» зелёный; workspace без флага не меняется |

| **S2** | Use cases + journeys | Закрытие (сидирование + лимит одной операцией), инвариант прерывания (state-based снимок), «Уже знаю» без лимита — journeys зелёные |
| **S3** | Инварианты билдера | NewCardPolicy; Exclude режет впрыск и избранное; journeys «незнакомая не в ревью (включая избранную)», «фразы как раньше»; старые тесты зелёны при Inject |
| **S4** | UI показа | 3 слайда, action bar с ConfirmModal, полоса, «Уже знаю» через MarkKnown, автозвук; wasm-тесты |
| **S5** | UI тренировки | Витки с шафлом, подфазы, направление, RatingButtons с новыми лейблами, заморозка; wasm-тесты |
| **S6** | UI завершение | Переход к ревью, empty state, прерывание; wasm-тесты + ручной smoke (reduced-motion, аудио в WebView). Итоговый экран удалён F-итерацией: закрытая рука сразу открывает ревью |
| **S7** | E2E | Playwright happy path + прерывание + «Уже знаю»; до согласования CI-job'а — локальный прогон под флагом как ворота среза |

> воспроизводится без изменений фичи. Рабочий локальный прогон:
> `cargo test --workspace --exclude origa_landing -j 2` + отдельно
> `cargo test -p origa_landing`. CI (Linux) продолжает покрывать полный

## 10. Стратегия верификации

### 10.1 Пирамида (~57 автоматических кейсов)

```
        ┌─────────────┐
        │  E2E  (L5)  │            3 сценария Playwright
       ┌┴─────────────┴┐
       │ WASM (L4)      │           ~15 кейсов, двойной прогон под флагом
      ┌┴────────────────┴┐
      │ Journeys (L3)     │         ~10 journey-тестов
     ┌┴───────────────────┴┐
     │ Домен: сидирование+пул│        ~12 кейсов
    ┌┴───────────────────────┴┐
    │ Домен: машина руки (L0)  │     ~35 rstest-кейсов
    └──────────────────────────┘
```

**L0 машина руки** (`domain/acquaintance.rs`, rstest в модуле): валидации `new()`
(Phrase/дубликаты/пустота/порядок); Counted 1→2→3; ProgressFrozen;
SubphaseAdvanced с обнулением; HandCompleted; смешанная рука; рука без слов;
вырожденная из 1; параметризация критериев по типам.

**L1 сидирование и пул**: seed-инварианты (!is_new, due=завтра, !is_known_card,
!high_difficulty — фиксированные часы); эволюция apply_review(Good): интервал
≥1 дня и короче потолка; merge-совместимость; матрица размера руки
min(7, пул, лимит) и JLPT-порядок helper'а.

**L3 journeys** (`use_cases/tests/journeys/`, state-based AAA):

| Journey | Фиксирует |
|---|---|
| `complete_hand_seeds_tomorrow_and_spends_limit_once` | закрытие: due=завтра всем, лимит +N одной операцией |
| `interrupted_session_leaves_repository_identical` | эфемерность: снимок до == после |
| `mark_known_from_presentation_skips_daily_limit` | «Уже знаю» без лимита; все отмечены → рука исчезла |
| `favorited_unknown_card_never_reaches_review_under_exclude_policy` | инвариант избранного |
| `new_phrase_goes_straight_to_review` | фразы вне режима |
| `imported_new_cards_enter_general_pool` | импорт через общий пул |
| `hand_completed_across_day_boundary_books_limit_on_completion_day` | смена суток |
| `card_deleted_mid_training_completes_hand_when_criteria_met` | удаление посреди руки |
| `fresh_user_lesson_is_hand_only` | холодный старт |
| `skipped_days_do_not_grow_hand_beyond_limit` | пропуск дней |

**L4 WASM** (двойной прогон): слайды трёх типов (фуригана по known_kanji;
знак кандзи с анимацией черт; тег типа карты; грамматика целиком через
